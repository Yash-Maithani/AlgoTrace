Searching

{{ counts.searching|words|capitalize }} algorithms. All figures below describe the implementations in algotrace/algorithms/searching/.

Linear Search

Walk the list from the start and stop at the first match.

Best
Worst
Space

Ruling a value out means looking at every position, so a failed search always costs the full n.

Binary Search

Halve the remaining range on every comparison. Needs a sorted list.

Best
Worst
Space

The iterative form keeps three markers and no recursion, so its extra memory does not grow with the list.

Jump Search

Jump ahead a block of about √n values at a time, then scan one block. Needs a sorted list.

Best
Worst
Space

Between linear and binary search: at n = 1024 its worst case is 64 comparisons, against 1024 and 11.

Sorting

{{ counts.sorting|words|capitalize }} algorithms. All figures below describe the implementations in algotrace/algorithms/sorting/. The last two never compare two values.

Bubble Sort

Compare each neighbouring pair and swap them if they are out of order.

Best
Worst
Space

No early exit, so even a sorted list costs n(n-1)/2 comparisons. The textbook O(n) best case needs a swapped flag.

Selection Sort

Scan for the smallest remaining value and move it into place.

Best
Worst
Space

The inner scan never stops early, so the comparison count does not depend on the input at all.

Insertion Sort

Take the next value and slide it back until it sits in order.

Best
Worst
Space

This one does break out of the inner loop early, so an already sorted list really is linear here.

Merge Sort

Split the list in half, sort both halves, then merge them.

Best
Worst
Space

Merging builds temporary lists, so the extra memory grows with the input rather than staying constant.

Quick Sort

Partition around a pivot so small values land left and large ones right.

Best
Worst
Space

The pivot is the last element, so an already sorted list is the worst case and the recursion reaches depth n.

Heap Sort

Build a max heap, swap the top to the end, then repair the heap.

Best
Worst
Space

The fast best case needs every value equal, so no repair moves anything; on distinct values every case is n log n. Heapify here is recursive, so the call stack is the extra memory rather than the usual O(1).

Counting Sort

Count how often each value from 0 to 99 appears, then write the list back from the counts.

Best
Worst
Space

No comparisons at all, which is how it gets under the n log n limit for comparison sorts. It only takes whole numbers 0 to 99.

Radix Sort

Deal the values into ten buckets by the ones digit, collect them, then do the tens.

Best
Worst
Space

d is the digits per value, here 2, and b the 10 buckets. No comparisons, and equal values keep their order.

Graphs

{{ counts.graphs|words|capitalize }} algorithms. V is the number of nodes and E the number of edges. Topological sort reads its edges as one way arrows, and A* works on a grid, where V is the number of cells.

Breadth-First Search

Visit everything one step away, then everything two steps away.

Time
Space

The queue is a plain list, so taking the front is O(V) and the duplicate check scans it once per edge. With a deque and a set this would be the familiar O(V+E).

Depth-First Search

Follow one branch to its end before trying the next.

Time
Space

Taking from the end of the stack is cheap, but the same duplicate check scans the stack once per edge.

Topological Sort

Kahn's algorithm: keep placing a node that no remaining arrow points at.

Time
Space

The queue is a deque, so every node and every arrow is handled a fixed number of times. A cycle stops it and is named.

Dijkstra's Algorithm

Always settle the nearest unvisited node next.

Time
Space

The next node is picked with a linear scan over every unvisited node, not a priority queue, so this is the V squared form.

A* Search

Expand the cell with the lowest cost so far plus a guess of the cost to go.

Best
Worst
Space

A binary heap on a grid of V cells. With the guess set to 0 the same code is Dijkstra, and a button runs both on your grid.

Prim's Algorithm

Grow a single tree, always taking the cheapest edge leaving it.

Time
Space

Uses a real heap, so every edge costs a log E push and pop.

Kruskal's Algorithm

Sort every edge, then take the cheap ones that do not close a loop.

Time
Space

The sort dominates. Union-Find uses path halving and union by rank, so the cycle check is nearly constant.

Bellman-Ford

Relax every edge repeatedly until nothing improves.

Time
Space

Stops early when a pass changes nothing, then makes one extra pass to detect a negative cycle.

Floyd-Warshall

Ask, for every pair, whether going via some third node is shorter.

Time
Space

Three nested loops over every node, and a full distance matrix held in memory.
