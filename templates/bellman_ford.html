Bellman-Ford Algorithm

Bellman-Ford finds the cheapest route from one start node to every other node, like Dijkstra, but it can handle negative edge costs.

It goes through every edge again and again, lowering distances, until a pass changes nothing.

If a distance still drops after that, the graph has a loop whose costs add up to less than zero, and it says so.

How long it takes and how much memory it needs, for the code on this site, are in the Complexity tab of the Learn panel, with the reason for each figure.

Good for

  • Shortest routes when some costs are negative, such as gains as well as losses.
  • Spotting a loop that keeps getting cheaper, such as a run of currency exchanges that ends with more money than it started.

Edges here go both ways, so a single negative edge is already a loop below zero: walk it there and back. The run reports it as one.
